1 · The territory

What sits where

The Hub is already Kurt's. The two systems below it are the ones being handed over — the Builder, which people use directly, and the bundle, which produces the numbers the Hub displays.

The service account named n8n-workflow-builder@ is shared — it runs the chat UI, the MCP server, n8n-ops and the Hermes VM, around eight services in all. You need iam.serviceAccountUser on it to deploy, and it's worth checking who else is attached before changing anything about it.

5 · How the Time-Saved KPI is computed

This is the part that gets questioned in reviews, so it's worth knowing precisely.

  • Primary source — each linked workflow's native timeSavedPerExecution (minutes), set by the workflow owner in n8n's settings panel. Per workflow: success_runs × value / 60.
  • Fallback — when no workflow on an initiative has a fixed value, expected_impact is used instead, normalised against the KPI's unit and period.
  • Fixed vs dynamic mode matters. n8n lets owners set time-saved either as a fixed number or dynamically via canvas nodes. The public REST API doesn't expose dynamic values, so dynamic-mode workflows contribute zero to our KPI while still showing a value in n8n's own Insights view. Recommend fixed mode to anyone whose workflow feeds a KPI.
  • Onboarding is gated on a secret. A KPI reports through this path once a per-KPI token exists at kpi-webhook-token-<id> in Secret Manager. Exactly one exists today, so exactly one KPI currently reports this way.
